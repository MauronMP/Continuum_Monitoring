# Research method

## Architectural claim

The proposal separates a reusable physical-continuum core from monitoring
experiments. Policies govern the selected monitoring plan; an ontology represents
resources, context and relationships. Wellbeing/stress is the motivating domain,
not the only possible domain and not a clinically validated outcome.

The historical scientific acquisitions belong to the first two batteries documented in
[Experiments](EXPERIMENTS.md). Battery 1 measures infrastructure/placement costs
and contains local policy-plan diagnostics. Battery 2 compares three alternative
decision implementations per host. Battery 3 now provides containerized scalability
on the same hosts, with distinct participant and physical-resource accounting;
engineering acceptance runs are not full scientific campaigns. The planned four-strategy extension is not
implemented and requires raw observations and independent acceptance criteria.

## Mechanism versus model

Class/property declarations describe possible knowledge. They do not execute
actuation, learning, privacy enforcement or mobility. A conceptual architecture
can contain components that are not yet implemented; label them accordingly.
The full modular ontology and the comparison adapter's small RDF projection have
different scopes. Procedural decision logic must not be described as consuming
an unrelated timed reasoning probe.

## Fair comparison

Fix workload, topology and semantic identity within a campaign. Use matched
node/size/repetition blocks, deterministic input traces, explicit warm-up and
separate initialization/steady-state metrics. Compare equivalent operational
requirements, not representation-specific policy identifiers. A faster or more
accurate semantic outcome must be observed, not assumed.

If procedural rules encode the same knowledge they can produce identical plans.
Potential modularity advantages require an explicit change scenario and measured
maintenance effort or generalization; functional agreement alone does not show
that advantage. Published systems are methodological references unless their
actual implementations are evaluated under a matched protocol.

## Physical and statistical limits

Real VPN deployment provides real transport effects, not a controlled distance
experiment. Record conditions and do not infer kilometres from IPs. Nominal network
capacity is metadata, not a throttle or measured available bandwidth.

Retain all planned outcomes. Failed/censored points delimit capacity; success-only
curves can bias conclusions. CPU, Python RSS, child-process peaks and elapsed
latency are different metrics. Five repeated jobs are not five independent
physical deployments. Report the replication unit and effective sample counts.

## Evidence workflow

Install using [Installation](INSTALLATION.md), acquire using
[Complete execution](COMPLETE_EXECUTION.md), inspect the records described in
[Outputs](OUTPUTS.md), and state the boundaries in [Ontology review](ONTOLOGY_REVIEW.md)
and [Ontology distribution](ONTOLOGY_DISTRIBUTION.md). Never regenerate missing
measurements from illustrative plots or retrofit historical outputs to new builds.
