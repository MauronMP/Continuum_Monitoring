# Results and Figures

Each run is `outputs/<run-id>/`. It contains campaign and environment manifests, exact configuration, topology, canonical scenario datasets, separate warm-up evidence, and independent layout/repetition directories. Every layout directory contains `cold-start.json`, proving that all workers were restarted and semantically verified before its warm-up. `semantic-contract/` snapshots the canonical base, all Turtle sources, both semantic manifests, and all 113 query files used by the run. Every repetition records worker health before preparation and after the query catalog, phase timings and digests, logical and physical query records, catalog-round totals, container states/image digests, and one-second Docker resource samples. Partial failures are preserved.

`summary/` contains `scalability.csv`, `preparation.csv`, `queries.csv`, `resources.csv`, `node_resources.csv`, `failures.csv`, `failure_causes.csv`, and `summary.json`. `preparation.csv` preserves per-node partition, serialization, transfer, remote-load, RDFS, byte, triple, and digest evidence. `figures/` contains nineteen PNGs for ABox/closure growth, preparation, reasoning, query percentiles, logical throughput, CPU, memory, payload bytes, the completion frontier, layout comparison, per-node resources, category/query cost, the transfer-throughput trade-off, relative layout cost, and node compute contribution. `figures/manifest.json` records the generated files and whether the category metadata fingerprint matches the campaign. Timeouts and transport failures remain categorical. Three repetitions support descriptive medians and observed ranges, not strong inferential claims.

- `scalability.csv` is the scenario/layout table: population, actual triples, dataset identity, completion count, timing medians, logical query percentiles/throughput, CPU, memory, network counters, and failures.
- `preparation.csv` is per repetition and node. It is the source for phase-cost and semantic-validation analysis.
- `queries.csv` contains logical-query observations. Per-repetition `physical_queries.json` preserves each worker execution separately.
- `resources.csv` is the unaggregated timestamped Docker/cgroup series. Missing or errored samples remain visible.
- `node_resources.csv` aggregates CPU and memory by physical node only for completed measured repetitions.
- `failures.csv` contains repetition failures and logical query errors without replacing timeouts by numeric values.
- `failure_causes.csv` gives a compact count by normalized transport, timeout, semantic, or memory cause.
- `summary.json` mirrors the main aggregate table for programmatic use.

Figures `01` and `02` verify ABox and materialized-graph growth. `03` and `04` show total preparation and its non-reasoning phases. `05` isolates RDFS. `06` and `07` show logical SPARQL latency percentiles and throughput. `08` and `09` show CPU and container-memory distributions from completed repetitions. `10` compares RDF payload volume. `11` identifies the observed completion frontier. `12` separates completed and failed repetitions by layout and population. `13` and `14` expose per-node CPU p95 and peak memory. `15` compares median and p95 query cost by semantic category. `16` identifies the fifteen logical queries with the highest campaign-wide p95. `17` relates transferred RDF payload to useful logical throughput and labels each measured population. `18` expresses the distributed cost change against replication as a percentage: positive values are reductions and negative values are penalties. `19` compares both layouts at every population using absolute CPU time and each node's normalized share. Every scalability axis includes all configured population levels; a red cross or an empty heatmap cell denotes missing valid measurements rather than a zero value.

Population axes represent the sixteen configured experiment levels as ordered, equally spaced categories. This avoids compressing the high-load frontier from 10000 to 20000 users and makes adjacent campaign outcomes directly readable; the spacing must not be interpreted as a continuous numeric distance. Every figure labels all populations (`1`, `50`, `100`, `500`, `1k`, `2k`, `4k`, `5k`, `6k`, `7k`, `10k`, `12k`, `14k`, `16k`, `18k`, and `20k`); labels are rotated rather than omitted.

Generated campaigns are ignored by Git. `outputs/README.md` remains versioned as the format guide. Before publication, retain one explicitly selected campaign, its manifest, raw evidence, summaries, and figures; do not combine repetitions from different semantic or query fingerprints.
